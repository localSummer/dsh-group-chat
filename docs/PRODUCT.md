# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

产品所有者本人——本地部署 DSH 的重度用户。在日常工作流（编码、方案设计、评审）中把「模型群聊」当作个人生产力工具：多模型观点对比、头脑风暴、方案评审。没有已确认的第二受众；若未来面向社区发布，需重新确认使用场景。

## Product Purpose

在 DeepSeek Harness Web GUI 内提供一个多模型角色群聊面板：用户创建若干角色（人设 + 标识色），每个角色绑定不同的 provider/model，在同一个群内围绕主题与群组工作区目录进行多轮对话。成功 = 用户能在一个界面内完成「配置角色 → 绑定工作区 → 发起讨论 → 观察多角色多轮交锋」的完整循环，而不必在多个会话/工具间搬运上下文。

## Positioning

角色扮演协作场：价值核心是**角色人设驱动的多智能体协作讨论**（如产品经理 × 工程师 × 评审各绑不同模型）。DSH 内的邻近能力（普通会话、子代理）都无法以「一个共享对话流 + 每角色独立模型路由 + 共享工作区目录」的方式组织这场讨论。

## Operating Context

- 运行于本地 DSH Web GUI（http://127.0.0.1:3080），作为 `~/.dsh/profiles/web` 的持久化双平面插件（`plugins/dsh-group-chat`）
- 使用流程：侧边栏「群聊」入口 → 左栏导航定位群组/会话（搜索过滤）→ 右栏配置群组工作区目录与角色（角色-模型绑定、深度思考开关；编辑走滑出抽屉）→ 中栏在当前会话发送消息（可 @成员 点名，或 @工作区内文件）或让角色自由讨论（1–10 轮，可随时停止）
- 与「任务看板」等 DOM 注入式社区插件同侧边栏共存：入口行度量对齐，点击群聊入口时对方自动收让中央列；对方激活（html 上的 `data-dsh-taskboard-active` / `data-dsh-ssh-active` 标记）时群聊入口视觉复位（外壳面板状态机不动，仅 CSS 复位，hover 反馈保留）
- 主会话⇄群聊切换（main keyed 槽整体卸载重挂）：浏览器半以模块级快照/选中缓存瞬时恢复上次视图（无加载闪现），挂载后经 state 拉取/SSE 首帧校正；lastCreated 定位信号仅在变化（真正的新建）时跟随选中，不再每帧重置视图
- 流式帧稳定性：SSE 全量快照（随消息数增长到数十 KB × ~7fps）每帧重建消息对象 identity——已完成消息在 host append 后不可变，Bubble 以渲染相关字段做值比较 memo，流式期间跳过已完成消息的全量重渲（含 MarkdownText 重新解析），防止多轮长会话下主线程饱和导致的「卡死后一次性蹦出」；每帧仅 live 行（流式正文/思考）与派生列表更新
- 设置面板「模型群聊」分区提供启停开关（settings.yaml 持久化）
- Host 半通过 `/api/group-chat/*`（回环 + 同源信任栏）服务浏览器半；角色发言经 `llm` 服务流式生成；群组工作区目录内经 `fs` 服务读取文本文件，注入每个角色的共享上下文

## Capabilities and Constraints

已确认功能：

- 群组管理：新建、重命名、删除（至少保留一个群组）；左栏搜索框按群组名/会话名过滤目录树
- 会话管理：每个群组内多个会话，左栏以「群组 → 会话」目录树呈现（展开/收起、新建、重命名、删除，至少保留一个会话）；消息挂在会话上
- **会话状态标识**（对齐主会话列表 StateDot 语义）：左栏会话行名称前状态点——进行中（蓝色像素追逐动画，含用户已点停止、run 未真正停完的窗口）/ 等待确认（琥珀，run_command 确认闸门挂起，优先级最高）/ 已完成（绿）/ 已出错（红，角色发言失败）；默认无点。「输出完毕」标记 = host 内存态 `run.finished`（不持久化、重启即清），查看即清（客户端选中该会话时经 `ackFinish` op 确认已读，覆盖点击/键盘/重挂恢复/lastCreated 定位全部选中路径，多端经广播同步）+ 新 run 启动即清；删除会话时同步清理悬空标记；状态派生为 core 纯函数（`sessStatus`，优先级：等待确认 > 进行中 > 已完成/已出错 > 默认）
- 角色（名称 / 标识色 / 人设 / 角色-模型绑定 / Temperature / 深度思考开关 + 推理级别（选项取自 DSH 模型设置的 reasoning.efforts，经 `efforts` 查询动作获取、60s 缓存；未配置或选「默认」= 不传 effort 用 provider 默认）/ 启用开关）挂在群组上，群组内全会话共享
- **群组工作区目录（共享资料）**：每个群组指定一条 `workspaceDir`（右栏手填或目录浏览器选定；支持 `~`、绝对路径、相对 DSH 工作区根解析），群内全会话共享。无独立文本笔记或文件清单。角色发言时 Host 经 `fs` 读取该目录**根下一层**文本文件（扩展名白名单、跳过隐藏项、最多 20 个），以 system 提示词「共享资料」块注入全体角色（单文件 16k / 总量 48k 截断）；未设置则不注入、不暴露工具。工作区文件内容不写入群聊存储，每次发言实时读盘
- 会话级主题；群内共享对话记录（最近 40 条注入每角色上下文，逐条 8k 字符截断）
- **会话标题/主题自动整理**（参照 oil-codex-title）：每轮对话结束后用 DSH 默认模型（经 `ctx.reflect.get('agentDefaultModel')` 可选读取——cordis 未 inject 的属性访问会抛错，服务缺位时静默跳过）后台生成，不产生消息、fire-and-forget、静默失败；名称 =「类别 emoji + 对象｜目标」（六类固定：🔎 调研对比 / 💡 头脑风暴 / ⚖️ 方案评审 / 🛠️ 排查修复 / 📝 方法整理 / 🗣️ 通用讨论，对象稳定、目标实质变化才改、省略群组名、语言跟随用户）；主题 = 演进式一句话摘要（对象 + 目标 + 当前焦点，每轮更新，注入后续角色上下文）；手动重命名会话 / 手动设置主题 = 隐式固定（namePinned / topicPinned 持久化于会话文件，自动整理永久跳过该字段）
- 多轮 round-robin 对话（1–10 轮），流式显示，可随时停止
- 消息正文以宿主同款 markdown 渲染（表格、代码块、公式）；开启深度思考的角色发言带可折叠思考行（折叠摘要 / 展开全文 / 流式实时跟随）——对标 DSH 自身会话流的呈现
- 面板为三区工作台：左导航（搜索 + 群组→会话目录树）、中会话流（贴底跟随、回到底部）、右上下文栏（角色卡 + 工作区目录，可收起，窄容器覆盖式）；角色编辑走右侧滑出抽屉
- 输入框支持 @ 快捷点名：裸 `@` 弹出成员候选（↑↓ 选择、Enter/Tab 插入）；`@` 后继续键入则在群工作区内检索文件（`fileSearch`，`~`/`/` 禁根），插入 `@path` 芯片（只把路径写入消息，不把文件正文再灌进 prompt，角色需 `read_file` 读取）。消息中被 @ 的成员优先作为本轮参与角色，并在角色提示词中注入「被点名优先回应」指引
- 设置页启停开关：关闭时中止进行中的对话并卸载侧边栏入口与面板
- **工具执行（TOOLS.md）**：设置工作区后角色可调用 `read_file`/`list_dir` 主动查看工作区（realpath 硬边界 + 分隔符比较，`../`、绝对路径、软链越界拒绝）；群组权限档位（composer 发送行左下角芯片，对齐主会话 `/permission` 三档：仅可查看 / 工作区内修改 / 完全权限，默认仅可查看，持久化于 ledger）决定命令能力——工作区内修改档角色可请求执行 shell 命令（cwd 固定工作区、超时 120s、输出采集 1MB 上限），每条命令在会话流内逐条确认（允许/拒绝/停止，命令全文展示）；完全权限档免确认直接执行（切换时弹主会话同款风险确认弹窗，勾选确认后才生效）；确认等待无限期，stop/热重载主动唤醒并 kill 子进程；工具调用以折叠行内嵌于角色消息（工具/参数/状态/耗时/输出），紧凑摘要注入后续发言上下文；护栏：单文件 100KB、单输出 8k、累计 32k（含每次调用 100 字符地板成本）、连续 6 次空输出/相同调用强制收尾（工具历史折叠为文本摘要收尾）；不支持 tools 的模型经 error finish 判定后去 tools 重试一次降级为纯文本
- **会话级文件持久化**：`~/.dsh/storages/group-chat/` 下每群组一目录、每会话一文件（`sessions/session-<uuid>.json` 自包含名称/主题/消息，含可选 `toolCalls`）；角色（`roles.json`）与工作区目录设置（`workspaceDir` 文件）随群组目录落盘；`ledger.json` 群组/会话清单（schema 3，群组属性含 `permissionTier`；v2 遗留 `allowCommands` 读取时迁移：true→工作区内修改、false/无→仅可查看）；事件驱动写（同 tick 合并；流式 partial 不落盘）；原子写（tmp+fsync+rename，每目录一次 fsync）；写失败保留脏标记重试；卸载时最终 flush 后释锁；单实例锁；损坏隔离重建（单会话坏仅丢该会话消息）；行级校验丢弃孤儿；schema 版本字段；全量保留不裁剪；锁不可得时降级内存态运行；v1 布局自动幂等迁移（旧 messages.json 归档不删除）

已确认约束：

- 群聊数据持久化于 `~/.dsh/storages/group-chat/`（重启 `dsh web` 后恢复）；设置 `enabled` 持久化于 settings.yaml；进行中的对话运行态（run）不持久化
- UI 文案为中文；样式使用 DSW 主题 CSS 变量（明暗主题适配）
- 共享资料不是独立笔记或文件清单：唯一配置是群组 `workspaceDir`；注入只扫工作区根下一层（不递归），工作区文件内容不落进群聊存储
- 工具面收敛为三件套（read_file/list_dir/run_command）；命令内容不做黑名单过滤（主防线 = 默认仅可查看 + 工作区内修改档逐条确认 + 完全权限档风险确认弹窗 + 命令全文展示）；正常工具调用次数不设上限；不改动 DSH 源码（纯外挂插件）

## Product Principles

1. **角色先于模型**：讨论的组织单位是角色（人设、立场、发言顺序），模型只是角色的执行器
2. **一份共享上下文**：对话记录与工作区资料对全群透明共享，任何角色发言都建立在同一信息面上
3. **本地优先**：数据在进程内、API 只服务回环同源，不引入外部服务
4. **与宿主共存而非接管**：遵循 DSH 插槽系统与主题变量，与社区插件对齐互让
5. **可中断、可观察**：流式输出 + 随时停止，长对话与资料有截断护栏
